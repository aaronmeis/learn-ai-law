# 4 · Redline-assist prompts

Work a contract **clause by clause** — what it does, who it favours, what the
fallback ask is. This pillar is **conceptual**: you are learning the clause
taxonomy and negotiation positions, not producing a marked-up draft for a real
deal.

## 🔒 Inputs — public exemplars only

Use only: **published vendor terms** (OpenAI Business Terms, Anthropic Commercial
Terms, Google Cloud Generative AI Indemnified Services, Azure OpenAI terms, AWS
Service Terms Sec. 50), **standard templates** (Common Paper Standard AI Addendum,
Bonterms Standard AI Addendum, SCL AI Clauses, oneNDA / oneDPA), or a **clause
you or the model drafts as a teaching example**. Never a real agreement under
negotiation.

**Model:** Sonnet 5. **Curriculum fit:** Weeks 3–4; capstone part 2.

---

## 4.1 — Clause anatomy pass

```
This is a PUBLIC exemplar for study — «name the source, e.g. "OpenAI Business
Terms, May 2025, Sec. 7 (Indemnification)"». Text:

«paste the clause»

Break it down:
1. What this clause is (in the standard clause taxonomy) and what job it does.
2. Plain-language paraphrase, sentence by sentence.
3. Who it favours as drafted — vendor or customer — and how you can tell.
4. The hidden mechanics: defined terms it leans on, cross-references, carve-outs,
   conditions precedent (e.g. "must use the latest model", "must not disable
   filters").
5. What's NOT said that a customer would want said.
6. How this compares to the market default (cite Common Paper / Bonterms / the
   other major vendors).
```

---

## 4.2 — Negotiation-positions table

```
For the clause type «e.g. output-IP indemnification / limitation of liability /
data-use for training / model deprecation notice», build a negotiation table:

| Sub-point | Vendor's opening position | Customer's ideal ask | Realistic fallback | Why it matters |

Ground each row in a real public example (name the vendor or template). Then:
the 3 sub-points a customer should never concede, and the 3 that are usually not
worth the fight.
```

---

## 4.3 — Conceptual redline of a public clause

```
Public exemplar for study — «source». Clause:

«paste»

Give me a CONCEPTUAL redline (not a rewrite for signing):
- Bracketed edits with a one-line rationale each, phrased as a customer-side
  reviewer would.
- For each edit, the fallback if the vendor rejects it.
- The 1–2 edits that are "walk-away" issues vs "nice to have".
- A 3-sentence summary I could say out loud to explain the redline to counsel.

Keep it educational — the goal is that I understand *why* each move, not that I
produce a filing.
```

## 4.4 — Compare how the market handles one clause

```
Show me how these PUBLIC sources each handle «clause topic»:
OpenAI, Anthropic, Google Cloud, AWS Bedrock, Azure OpenAI, Common Paper AI
Addendum, Bonterms AI Addendum.

Table: source × the sub-points that matter, cells = actual position with a short
quote. Then: which is most customer-favourable and why, which is most vendor-
favourable, and what a "reasonable middle" clause would contain.
```

## 4.5 — Spot the trap

```

protective but aren't, the carve-out that swallows the rule, the defined term
that's narrower than it sounds, the condition that's easy to breach
unknowingly. For each trap, how it would bite in practice and what language
neutralises it.

```
