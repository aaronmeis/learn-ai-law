# 5 · Translation prompts

Move between registers: legalese ↔ plain English ↔ technical framing. Use these
to prep for conversations with counsel and to pressure-test whether you actually
understand something.

**Model:** Sonnet 5. **Curriculum fit:** every week; especially before any
counsel conversation and the Week-6 mock.

---

## 5.1 — Legalese → plain English

```
Translate this into plain English for a technical audience, keeping every legal
nuance that matters. Flag any word that is a term of art (has a specific legal
meaning I shouldn't read colloquially). Note anything ambiguous that a lawyer
would want clarified.

«paste statute / clause / holding»
```

---

## 5.2 — Technical → legal framing

```
I'm going to describe an AI system / data flow in technical terms. Re-express it
the way a lawyer needs to hear it: what are the legally-relevant facts, which
roles attach (controller/processor, provider/deployer, licensor/licensee), what
triggers which obligation, and what facts are still missing that counsel would
ask for first.

«technical description»
```

---

## 5.3 — Prep for a counsel conversation

```
I have a conversation with «in-house counsel / outside counsel / the privacy
team» about «topic». Help me prep:
1. The 5 questions I should ask, phrased precisely.
2. The context I should give them up front (facts, not conclusions).
3. The vocabulary to use so I'm understood quickly.
4. What NOT to assert (things that are counsel's call, not mine).
5. How to capture their answer so I can act as the liaison afterward.
```

---

## 5.4 — Two-audience summary

```
Summarise «case / regulation / development» twice:
- For an executive: 4 sentences, "what changes for us and by when".
- For a lawyer: the precise version with citations and the open questions.
Then one line on how I'd bridge the two in a meeting.
```

---

## 5.5 — Jargon decoder

```
Define these as I'll encounter them in AI-law reading, with a one-line example
each and the contrast term they're often confused with:
«list terms — e.g. indemnify vs defend vs hold harmless; provider vs deployer;
open weights vs open source; controller vs processor; transformative vs
derivative»
```

---

## 5.6 — "Is my mental model right?"

```
Here's my current mental model of «topic», in my own words: «...»
Tell me where it's accurate, where it's an oversimplification that will mislead
me at rung 300, and where it's just wrong. Give me the corrected model in the
same plain register I used.
```
